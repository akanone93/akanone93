# studio — Agent Notes

The Bun workspace for Plux Studio (spec §21): `apps/` for the web app and backend-for-frontend, `packages/` for shared libraries. Studio code is AGPL-3.0-only (ADR-0022). Read [typescript-standards.md](../docs/engineering/typescript-standards.md), [studio-development.md](../docs/engineering/studio-development.md), [studio-ui-language.md](../docs/engineering/studio-ui-language.md) and the root [AGENTS.md](../AGENTS.md) before editing.

## Layout

| Path | Contents | Arrives |
|---|---|---|
| `packages/brand/` | Brand tokens (spec Appendix J) and WCAG contrast utilities | P0 |
| `packages/schema/` | Contracts generated from `schema/`: limits now; document types and widget and action registries as they arrive (`SCH-001`, `WGT-002`) | P1 |
| `apps/web/` | React single-page application | P11 |
| `apps/bff/` | Bun backend-for-frontend (`STU-002`, `SEC-101`) | P11 |
| `packages/layout/` | TypeScript port of Flutter's layout code (`STU-005`); imports no React | P11 |
| `packages/canvas/` | Plux Canvas: CanvasKit scene, drawing and hit-testing (`STU-003`) | P11 |
| `packages/api/` | Generated Connect-ES clients and query hooks | P11 |
| `packages/ui/` | Shared components of the UI language and their catalogue | P11 |
| `packages/i18n/` | Lingui catalogues and locale handling (`en`, `de`, `ar`) | P11 |
| `packages/validator/` | The Go validator compiled to WebAssembly and its worker | P11 |

## Invariants

- TypeScript is strict (see `tsconfig.json`); no `any`, no non-null assertions, no `console` in shipped code.
- Dependencies are installed exactly as locked (`bun install --frozen-lockfile`); `bun.lock` is committed.
- Brand values come from `@plux/brand`; they change only together with spec Appendix J (`STU-016`).
- Files named `*.gen.ts` are generated by `make gen` and never edited; Biome skips them and `tsc` checks them.
- Studio never talks to the database or object storage directly; all access goes through the API (layering rule L-7).

## Feature areas of `apps/web/src/features/`

One folder per area; each has an `index.ts`, its screens, a `<area>.messages.ts` and tests. Read the
folder, its `*.messages.ts` and the spec section named in the file headers before editing it. Work
on one area per session ([studio-development §13.8](../docs/engineering/studio-development.md)).

| Area | Folders |
|---|---|
| Shell, sign-in, profile | `shell/`, `auth/`, `profile/`, `home/`, `notifications/` |
| Canvas and editing | `app-canvas/`, `plugin-canvas/`, `editor/` (edit pipeline, undo, locks, conflicts), `history/`, `preview/`, `overlay/`, `panels/`, `problems/`, `safety/` |
| Designers | `action-graph/`, `state-designer/`, `designers/` (data source, database schema, theme), `json-editor/`, `rust-editor/` |
| Publishing | `publish/`, `releases/`, `approvals/` |
| App areas | `functions/`, `data/`, `localisation/`, `design/`, `library/`, `analytics/` (usage, funnels, errors, replays), `experiments/` (experiments and flags), `tests/` (Plux Test), `devices/`, `security/` |
| Administration | `admin/`, `installation/` |

User-facing guides for these areas are in [docs/guides/studio](../docs/guides/studio/README.md); the BFF
is operated by [docs/operations/studio-bff.md](../docs/operations/studio-bff.md). A change to a
screen's labels or flow updates its guide in the same pull request.

## Rules for code

- **Strings.** No literal UI text, raw style values, physical-direction properties or `innerHTML`:
  Biome plugins in `lint/*.grit` reject them (`no-literal-ui-strings`, `no-raw-values`,
  `logical-properties`, `no-inner-html`), and `lint/lint.test.ts` proves each with a good and a bad
  fixture in `lint/fixtures/`. Use the components of `packages/ui` (read `CATALOGUE.md` first).
- **Lingui recipe for a new string.**
  1. Add it to the area's `<area>.messages.ts` as `i18n._({ id: "<area>.<name>", message: "…", comment: "…" })`
     inside the `…Messages(i18n: I18n)` function; the stable key and the translator comment are
     required. Use ICU plural and select forms, never string concatenation.
  2. In a component, `const m = areaMessages(useLingui().i18n)`; there is no global catalogue.
  3. From `studio/`, run `apps/web/node_modules/.bin/lingui extract --clean`. It rewrites
     `apps/web/src/locales/{en,de,ar}/messages.po`.
  4. Fill the `msgstr` of every new or changed entry in `de` and `ar` (`en` holds the source text).
  5. `lingui compile --strict` must pass with no missing entry. `make studio-i18n-check` runs 3
     and 5 and fails when the committed catalogues differ from a fresh extract. Commit the `.po` files.
  Tests that render the app load the English `.po` through `loadSourceCatalogue()`
  (`apps/web/src/test-harness.tsx`), so a new key must be extracted before its test passes.
- **Workers get cloneable data only.** Everything posted to the canvas, validator or lock worker
  must survive `structuredClone`: plain objects, arrays, numbers, strings and typed arrays. Never a
  function, class instance, `Promise`, DOM node or React ref (a font loader in the surface size once
  stopped the canvas from starting). Message types live in `packages/canvas/src/protocol.ts` and
  `protocol.test.ts` clones every message; add yours to both. Pass dimensions and ids, not objects
  that carry behaviour. Workers are created through `lib/trusted-worker.ts` (Trusted Types policy
  `plux-worker`, `worker-src 'self'`, no `blob:`).
- **Canvas ownership.** The canvas draws and hit-tests; React does not render the scene. A property
  edit reaches the scene as a JSON Patch from the edit pipeline (`features/editor/`), never as props.
  Tests assert on the scene model (`packages/canvas`, `buildSceneModel`), not on pixels.
- **Generated files** (`*.gen.ts`, `theme.gen.css`, `packages/api` clients, `icons.gen.ts`) come from
  `make gen`, `make studio-gen-theme` and `make studio-gen-icons`; never edit them.

## Rules for tests

- `bun test` with happy-dom and Testing Library (`bunfig.toml`, `test-setup.ts`). Query by role and
  accessible name, not by class or structure; name the requirement ID in the test title
  (`test("… [STU-070]", …)`).
- **Whole-app tests use the in-memory upstream.** `renderApp(path, state)` from
  `apps/web/src/test-harness.tsx` renders the real router against `createUpstream(state)`
  (`test-upstream.ts`, with the admin fixtures in `test-admin.ts`): a Connect router transport that
  implements every service Studio calls from the plain-data fixtures in `state`. To cover a new
  screen, extend the fixture interface in `test-upstream.ts` for the RPCs it calls and record what
  the screen sends (the `decided`, `saved`, `putDocuments` style arrays) so the test asserts on
  requests as well as on the page. Do not mock `fetch` or the hooks. `Upstream.surface`, `validator`
  and `editor` replace the canvas surface, the validator worker and expose the edit session.
- **No `.toBeNull()` inside `waitFor`.** When it fails, Bun formats the received DOM element and the
  test stalls for about 25 seconds. The Biome plugin `lint/no-waitfor-tobenull.grit` rejects it; write
  `await waitFor(() => expect(x === null).toBe(true))`.
- **Base UI selects.** A `Select` from `packages/ui` is a `combobox` button with a popup of
  `option`s. In a test: `fireEvent.click(await screen.findByRole("combobox", { name }))`, find the
  `option`, wait about 400 ms (Base UI ignores a pick made at once after the popup opens), then fire
  `pointerDown`, `mouseDown`, `pointerUp`, `mouseUp` and `click` on the option, and assert on the
  combobox's text. Example: the "Font file" test in `features/design/design.test.tsx`. There is no native `<select>`, so
  `selectOptions` helpers do not apply.
- Behaviour tests run in `en`, `en-XA` and `ar-XB`; the Playwright locale sweep, axe checks and the
  flows in `e2e/` run in CI (`make studio-e2e`). `e2e/s3-flow.spec.ts` is the canvas flow end to end.
- Coverage floors are in `coverage.json` and are never lowered (`QA-001`).

## Required checks

`make studio-check` — frozen install, Biome, import boundaries (`make studio-bounds`), catalogues
(`make studio-i18n-check`), type-check, tests with coverage floors, the production build and the
bundle-size budget. Also, where your change touches them: `make studio-e2e`, `make studio-conformance`
(layout against Flutter's goldens), `make studio-bench-canvas`, `make studio-bench-overlay`,
`make studio-design-gate` and `make studio-image-repro`. `make studio-dev` runs Studio against the
Compose stack ([run it locally](../docs/guides/run-locally.md) §4).

`@plux/layout`'s text tests load Flutter's CanvasKit from `PLUX_CANVASKIT_DIR` (default: the pinned SDK's `bin/cache/flutter_web_sdk/canvaskit`); in CI `flutter precache --web` provides it.
