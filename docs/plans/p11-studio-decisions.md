# P11 Studio — Decisions

- **Status:** Decided by the maintainer in a preparation session on 2026-10-16 to 2026-10-18,
  before P11 starts. Binding input for the P11 plan and its ADRs. Nothing here is implemented.
- **Scope:** Plux Studio (`studio/`, spec §21, `STU-001`–`STU-123`): engineering decisions,
  with the reason where it is not obvious. Functional and operational decisions follow in a
  later session.
- **Not yet applied:** no existing document was changed. Spec wording changes, ADRs,
  allowlist entries and `proto/` changes listed in §5–§7 are still to be made, each in the
  pull request that needs it, with the maintainer's approval where `AGENTS.md` §7 requires it.
- **Measurements** marked *measured* were taken in that session (npm packages as of
  2026-10-16/18, the pinned Flutter 3.47.5 SDK, headless Chromium with software rendering).

---

## 1. Guiding rules from the session

1. **Protect the server.** Every Studio feature that adds server work is bounded: rate
   limits, size and count limits from the limits registry (`LIM-001`), capped history
   rebuilds, queued worker jobs with per-organisation limits, precompressed static assets.
   A design that moves work to the server must say how it is bounded.
2. **Legal care.** Every licence question (fonts, ported code, copyleft test tools, Apple
   fonts) gets a legal review before its ADR is accepted. Nothing third-party is
   redistributed unless its licence clearly allows it; when in doubt, it is not shipped.
3. **Best performance first** within the spec's priority order (security and correctness,
   then performance).
4. **Every new dependency** needs an allowlist entry and an ADR first
   ([dependencies.md](../engineering/dependencies.md)). Versions below are those checked in
   the session; pin exact versions when adding them.

## 3. Decisions with reasons

### 3.1 React SPA, not Next.js
Studio is a client-heavy editor behind sign-in; server rendering and SEO give nothing, and
`STU-001`/`STU-002` already require a React SPA with a Bun BFF.

### 3.2 State: Zustand + Immer
- Selector subscriptions re-render only what changed; the vanilla store works outside React.
- **Stores are per area, created in a React provider**, never module-level singletons
  (`AGENTS.md` §8, rule book §6.1).
- Immer produces forward and inverse patches: the source of undo and the JSON Patch autosave.
- The edited document lives in the Zustand store; TanStack Query holds server-confirmed data.

### 3.3 Canvas renderer: CanvasKit
- **Deciding reason — text layout.** On the device, Flutter lays out text with Skia's
  SkParagraph, also under Impeller (verified in the engine source:
  `lib/ui/text/paragraph_builder.cc` → `txt::ParagraphBuilder::CreateSkiaBuilder`;
  `txt/src/skia/paragraph_builder_skia.cc` → `skia::textlayout::ParagraphBuilder::make`).
  CanvasKit runs the same code in the browser; every other option measures text with the
  browser and cannot match `STU-005`. Flutter itself removed its browser-text HTML renderer
  in 3.29.
- Painting is Skia's model (rounded rects, blur shadows, gradients, clips, layers). The
  device paints with Impeller, so pixels differ slightly; the conformance suite compares
  positions and sizes, not pixels.
- **Build our own CanvasKit from the Skia revision Flutter 3.47.5 pins**, trimmed (no Skottie,
  PDF, extras), as `plux-svgc` already builds Skia path ops (ADR-0027). Trimmed size to be
  measured.
- *Measured:* npm `canvaskit-wasm` 0.42.0 default build 2.80 MiB gzip, full 3.14 MiB; PixiJS
  8.22.0 231 KiB gzip. The 1.5 MiB budget (`STU-122`) covers initial JavaScript only; the
  canvas loads on demand, is prefetched while the apps grid is open, compiled with
  `compileStreaming`, cached as immutable.
- Costs: size; manual `.delete()` (one ownership wrapper plus a leak check in tests); the
  canvas needs a parallel accessible DOM tree (true for any WebGL option).

### 3.4 Layout engine: custom port of Flutter's layout code
- Yoga and Taffy implement CSS layout. Flutter passes min/max constraints down and sizes up;
  `RenderFlex` (read in source) lays out inflexible children unbounded, splits only leftover
  space by flex factor (tight/loose), has no flex-shrink, keeps sizes on overflow, has its own
  `MainAxisSize.min` and baseline rules. Each difference fails `STU-005`.
- CSS engines cover only Row/Column/Flex/Stack/Wrap/Padding/Align/SizedBox of the 99 Layer 1
  widgets; slivers, LimitedBox, FittedBox, AspectRatio, FractionallySizedBox, Baseline and the
  Material/Cupertino composites (Scaffold, AppBar, ListTile, buttons) need custom code anyway.
- Incremental relayout (relayout boundaries) comes with the port, for `STU-121`.
- *Measured:* `yoga-layout` last release 3.2.1, December 2024; Taffy has no official JS binding
  (third-party `taffy-layout` 3.0.0, 207 KiB gzip); the relevant Flutter rendering files total
  about 24,000 lines including docs, debug checks and painting.
- **How:** port the box, intrinsic, baseline and sliver protocols and each render object from
  the pinned Flutter source into `studio/packages/layout`, recording the source revision per
  file. Text through SkParagraph with Flutter's rules (text scaler, strut, height behaviour,
  max lines, ellipsis).
- **Conformance suite:** headless `flutter_test` writes every node's global rect to golden
  JSON per widget × device frame × locale × text scale; the TS engine is compared in CI within
  the tolerance; a Flutter upgrade regenerates goldens and the diffs are ported.
- **Licence:** ported code keeps Flutter's BSD-3-Clause notice and gets a `REUSE.toml`
  annotation inside AGPL `studio/`; legal review (§1.2).

### 3.5 Action graph editor: React Flow + dagre
- A DOM overlay (`STU-063`), separate from Plux Canvas; nodes are small forms needing real
  DOM for input methods, focus and screen readers.
- Graphs are small and bounded (spec §9.4); 57 action types in `schema/actions`.
- React Flow gives pan/zoom, selection, connection dragging with `isValidConnection`, minimap,
  keyboard access and localisable `ariaLabelConfig`. It pins Zustand ^4, so a second copy
  ships beside Zustand 5 (a few KiB; note it in the ADR).
- Node types are generated from `schema/actions/*.json`: `branches` → named outputs;
  `onSuccess`/`onError` fixed outputs; `inputs` → node form.
- Path validation uses the compiler's rules via the WebAssembly validator (§3.7), never a TS copy.
- dagre (pure layout) also drives app-canvas auto-layout (`STU-032`) and screen auto-layout
  (`STU-050`).

### 3.6 Inline PXL editor: CodeMirror 6
- *Measured:* about 119 KiB gzip with autocompletion and lint, against about 685 KiB gzip for
  Monaco's core; cheap per instance (dozens per screen); styles like an input.
- Monaco stays for the full-screen JSON and Rust editors. Both use the same PXL language
  service (`PXL-008`).

### 3.7 Compiler validation in the browser
- The real Go validator (`compiler.NewValidator`, `ValidatePage`) compiled to WebAssembly,
  run in a Web Worker, one module shared with the PXL language service. The server validates
  again on save and publish and stays the authority.
- *Measured:* builds unchanged for `GOOS=js GOARCH=wasm`; 11.8 MiB raw, 3.1 MiB gzip. Loaded
  only when an editor opens.
- `ValidatePage` checks only the edited page and its graphs, fitting validation as you type
  (`STU-064`).
- Speed-ups if the prototype shows a need: one batched message per edit (avoid `syscall/js`
  chatter), split validation from encoding, try TinyGo; only then move project-wide checks to
  the server.

### 3.8 Styling: Tailwind CSS v4
- Required by `STU-001`; shadcn is written in it.
- Tokens from `@plux/brand` generate the `@theme` CSS variables; default Tailwind values are
  reset so only token-backed utilities exist (rule book §4.2). Themes and density switch by
  variables.
- Logical utilities for RTL. One static stylesheet: no runtime style injection, CSP-safe.

### 3.9 Routing: TanStack Router
- Typed routes, links and **schema-validated search params**: open app/plugin/screen,
  selection, zoom, device frame, locale, theme and open overlay live in the URL.
- Loaders prefetch Query caches; per-route code splitting; overlays are routes inside the
  canvas route, so the canvas never unmounts (`STU-063`).

### 3.10 Server data: TanStack Query + Connect Query
- Generated typed hooks and keys per RPC; optimistic mutations with rollback; keys include the
  document revision (ADR-0015).
- The editor's working copy stays in Zustand, not in the Query cache.
- Live streams (§4.2) bypass Query and go into Zustand.

### 3.11 Forms: TanStack Form + Zod 4
For the ordinary forms (new-app wizard, publish flow, admin, policies, settings). The
Properties panel uses no form library: descriptor-generated editors write JSON Patch into the
store and are validated by the WebAssembly validator.

### 3.12 Testing

| Layer | Tool |
|---|---|
| Logic, unit | `bun test` (already wired: LCOV, `make studio-cover`, 70% floor) |
| Layout conformance | `bun test` with CanvasKit headless (*verified*: SkParagraph layout runs under `bun test`, no browser or GPU) |
| Components | `bun test` + happy-dom + Testing Library |
| Real browser, end to end, canvas | Playwright (Chromium; software rendering works without a GPU) |
| Accessibility | `@axe-core/playwright` + keyboard-only walkthroughs |
| Locale sweep (rule book §12.4) | Playwright over the dev catalogue page (§3.22) in `en`, `en-XA`, `ar-XB` |
| Performance | Playwright traces (§4.6) |

No Vitest. If happy-dom is too thin for a component, test it in Playwright.

### 3.13 i18n: Lingui 6
- ICU MessageFormat (same standard as `I18N-001`), catalogues compiled at build time (small
  runtime, no parsing in the browser, CSP-friendly), typed message IDs.
- **Explicit keys** declared in `<feature>.messages.ts` with English text and a translator
  description (rule book §7.4); strict extraction fails on missing and unused keys.
- Locales `en`, `de`, `ar` (rule book §7.1); dates, numbers and plurals via `Intl` (CLDR).

### 3.14 UI components: shadcn/ui on Base UI
- shadcn is a generator: code is ours, styled with our tokens.
- Base UI is shadcn's default since July 2026, actively released, with focus management,
  keyboard navigation and a direction provider.
- **Maintainer chose Option A:** change `STU-001` to "shadcn/ui on Base UI primitives".

### 3.15 BFF: Hono + `oauth4webapi`
Hono ships CSRF, secure headers with per-request CSP nonces, cookies, body limit and timeout
middleware (checked in the package), has no runtime dependencies and runs on Bun natively.
`oauth4webapi` does the OIDC authorisation-code flow with PKCE.

### 3.16 Build: Vite 8 on the Bun runtime
- Official plugins exist for every chosen library (Lingui, TanStack Router, Tailwind v4,
  WebAssembly); `bun-plugin-tailwind` 0.1.2 is a year old and there is no Lingui Bun plugin.
- **Maintainer chose Option A:** `STU-001` "built with Bun" reads as Vite on the Bun runtime;
  make the wording explicit.

### 3.17 Monorepo layout
```
studio/apps/web          React SPA
studio/apps/bff          Hono BFF
studio/packages/brand    tokens, contrast (exists)
studio/packages/schema   generated contracts (exists)
studio/packages/api      generated Connect-ES clients
studio/packages/ui       shadcn components, CATALOGUE.md
studio/packages/layout   Flutter layout port (no DOM, no React)
studio/packages/canvas   Plux Canvas on CanvasKit (no React)
studio/packages/validator WebAssembly validator + PXL language service
studio/packages/i18n     catalogues, locale, direction
```
Dependencies point downwards only; `layout` and `canvas` never import React, so they test
headless.

### 3.18 Lint and format
Biome only, as today (`biome ci` in `make studio-check`).

### 3.19 Drag and drop
- Inside the canvas: Plux Canvas's own pointer handling.
- Insert panel → canvas, file and asset drops, panel lists: Pragmatic drag and drop (native DnD,
  DOM → canvas element with our own hit-testing, desktop files).
- Layers tree: Headless Tree (tree semantics, keyboard moves, virtualisation).
- Every drag has a keyboard alternative ("Move to…", nudging) for WCAG 2.2 (`STU-011`,
  `STU-067`).
- Not dnd-kit: classic 6.3.1 unreleased since December 2024; the rewrite is 0.5.1.

### 3.20 Virtualisation, charts, icons, animation
- **TanStack Virtual:** headless; rows, columns and 2D grids (localisation keys × locales),
  measured row heights (logs, audit); pairs with TanStack Table and Headless Tree.
- **Recharts 3** via shadcn Chart for dashboards (tokens, built-in accessibility layer);
  **uPlot** for the live device performance stream (`STU-066`).
- **Lucide** for Studio's own UI; the apps' icons stay the Material Symbols and Cupertino sets
  the server embeds. Lucide has no RTL-mirror metadata: the catalogue keeps the
  `mirrors: true | false` list (rule book §8.3).
- **No animation library:** required animations (bundle expansion 150–200 ms, ghost-screen
  pulse) run in Plux Canvas; panels and dialogs use CSS transitions with duration/easing
  tokens; reduced motion honoured.

### 3.21 Diff tooling
- Patches while editing: Immer → RFC 6902.
- Applying and diffing: `rfc6902` (`fast-json-patch` unreleased since 2022).
- Text diff: Monaco's diff editor over the server's canonical JSON (JSON editor vs last
  published, history compare).
- "What changed" lists (publish flow, history): our own diff keyed by entity UUIDv7
  (`SCH-002`) — correct moves, renames, adds without guessing array order.
- All diffing in the browser; the server only serves the two snapshots.

### 3.22 Component catalogue tooling
No Storybook or Ladle. A **development-only catalogue page** in the same Vite app renders each
shared component's states from `*.cases.tsx` files beside it (loading, empty, error, long text).
Playwright opens it in the three locales. `CATALOGUE.md` stays the written reference.

## 4. Architecture decisions

### 4.1 Threading: Plux Canvas in one dedicated Web Worker
- The worker owns layout, CanvasKit, scene graph, hit-testing and raster snapshot caches, and
  presents frames directly via `transferControlToOffscreen()` (no per-frame copy; Flutter's
  multi-threaded skwasm copies via `transferToImageBitmap`, reported slow in Firefox/Safari).
- The main thread keeps React, the Zustand document and undo, input capture and the accessible
  DOM tree. React work can never drop a canvas frame (`STU-120`, `STU-045`).
- One worker, not two: layout needs SkParagraph, so splitting would load CanvasKit and fonts
  twice.

| Flow | Path |
|---|---|
| Edits | edit pipeline → JSON Patch → autosave, undo, validator worker, canvas worker (one stream) |
| Input | pointer/wheel captured on main, coalesced per frame, posted; pan, zoom and drag run in the worker; a finished drag sends one patch back |
| Back channel | at most once per frame: selection, hover, bounds of changed nodes, layout diagnostics → panels, accessible tree (rule book §9.5), scene queries for tests (§9.2, now an async snapshot) |
| Text editing on canvas | DOM editor positioned from worker-supplied bounds |
| Drops from panels | main posts the drop point; the worker hit-tests |
| Fonts, images | bytes transferred without copying |
| Overlays (`STU-063`) | "pause" stops drawing; canvas stays mounted; state lives in the worker |
| Context loss | the worker rebuilds GPU resources from the scene model (§9.6) |

- No SharedArrayBuffer at first (needs cross-origin isolation); later optimisation only if the
  back channel measures as a bottleneck.
- The canvas module talks only through its message interface, so the same code runs on the
  main thread as a fallback for browsers that fail; `bun test` drives it directly.
- *Verified in headless Chromium:* `requestAnimationFrame` in a worker, WebGL2 on
  OffscreenCanvas, CanvasKit surface from the transferred canvas, 120 frames of 1,000 rounded
  rects. **Not verified:** Firefox, Safari, real GPU frame rates (prototype).

### 4.2 Live channels: Connect server streaming, no WebSocket
- Matches today's code: `WatchPublish` already server-streams (`proto/plux/v1/publish.proto`);
  the server speaks HTTP/1.1 and h2c (`backend/internal/server/server.go`); locks are unary
  leases (`plugin.proto`); the only WebSocket code is the device data-source gateway.
- Server → browser: server streams. Browser → server commands (send to device, edit device
  state, mocks, inspect selection): unary RPCs, well within `DEV-010`'s 500 ms.
- Per tab: **one events stream** (notifications, lock changes, publish progress) and **one
  stream per paired device**; HTTP/2 between browser and BFF (six-connection HTTP/1.1 limit);
  every stream resumes from a cursor with bounded server buffering (`DEV-021`).
- BFF (Hono) proxies streams unbuffered with the user's token, heartbeats and deadlines.
- Consequences:
  - Live lock and notification events need a server fan-out (e.g. PostgreSQL
    `LISTEN`/`NOTIFY`); `WatchPublish` polls today (`backend/internal/api/release.go`).
  - **Connect-Web in browsers supports only unary and server streaming**, so `UploadAsset`,
    `ImportDraft` and `UploadSource` (client streaming) cannot be called from Studio. They need
    unary chunked variants or a BFF upload endpoint — a `proto/` change (§7).
  - The device half of the streams is P10 (`DEV-020`); design its messages with that work.

### 4.3 Rust editor bridge (`FN-033`)
- LSP JSON-RPC carried over Connect: one server stream per editor session
  (`LanguageServer.Open`) and batched, sequence-numbered unary `Send` calls.
- Browser: `monaco-languageclient` with a small custom transport.
- **Security first:** rust-analyzer runs build scripts and proc macros (arbitrary code). It runs
  in the function build sandbox (ADR-0064, `L-4`: no credentials) with build scripts and proc
  macros off, no network, CPU/memory/time limits, one sandbox per session.

### 4.4 Fonts
- **Studio UI:** Noto Sans + Noto Sans Arabic (OFL-1.1, variable, self-hosted); one family
  across scripts (rule book §4.6) and covers later scripts (e.g. Ethiopic). Sora for the
  wordmark only.
- **Canvas, app fonts:** the worker fetches the same verified font assets the device loads
  (ADR-0032 § Fonts per script).
- **Canvas, platform defaults:** Studio ships Roboto for Material and Noto fallbacks per script.
  Roboto's current distribution is OFL-1.1 (not Apache-2.0 as said in the session) — verify the
  exact files' licence at import.
- **Fonts bundled in host apps:** proposed — `plux native scan`/`native sync` upload them with
  the native catalogue (additive; maintainer approval).
- **SF Pro — never served or stored by Plux.** Apple's licence forbids embedding and
  redistribution and allows only UI mock-ups for Apple platforms by registered developers.
  - Chromium: use the user's own installed SF Pro via the Local Font Access API
    (`queryLocalFonts`, with permission); bytes stay in the browser.
  - Firefox, Safari, or no SF Pro installed: a substitute plus the "device preview is
    authoritative" notice (`STU-006`).
  - Android device frames with Cupertino style: always the substitute (the licence forbids
    mock-ups for non-Apple systems).
  - **Counsel confirms before the ADR is accepted.**

### 4.5 Undo persistence (`STU-069`)
- Server-side, on the snapshots already stored for every accepted write (`SRV-031`). Nothing in
  IndexedDB (sensitive fields on disk, breaks across tabs/devices, diverges after a lock
  takeover `SRV-041`).
- The browser holds the in-memory stack; after a reload it rebuilds from this editing session's
  snapshots. Undo applies the inverse patch as a **new forward write** (ADR-0015 linear history).
- Proposed API addition: tag each write with an editor-session ID and store its inverse patch
  (`proto/` change, §7).
- Edits inside the 500 ms autosave delay flush on tab hide via `fetch` `keepalive` through the
  BFF.
- Server protection: inverse patches are a few hundred bytes; rebuilds capped to the session's
  recent entries; writes rate-limited.

### 4.6 Thumbnails, screenshots, visual diff
- App-card and ghost-screen thumbnails: rendered **in the browser** from the canvas's cached
  CanvasKit snapshots, uploaded only when changed (small, content-addressed, rate-limited).
- Publish visual diff: **server-side**, as `STU-100` requires ("rendered server-side on standard
  devices"), as a bounded, queued worker job with per-organisation limits from the registry.

### 4.7 Studio's own telemetry (minimal)
- The BFF starts W3C Trace Context on every proxied call (`OBS-001`); no browser SDK.
- Uncaught browser, canvas-worker and worker errors and real-user timings (LCP, long frames via
  `web-vitals`) go to one BFF endpoint, then to the server's structured logs (`OBS-003`
  redaction).
- No document content, personal data or sensitive fields; sampled and rate-limited at the BFF;
  an administrator switch turns it off. No third-party services (rule book §11.5).

### 4.8 Browsers, reference laptop, performance CI
- **Reference laptop** is already defined (§30.1): 4-year-old mid-range laptop, integrated GPU,
  Chromium-based browser. No GPU purchase. `STU-120` is confirmed by hand on it before each
  release; results go to `docs/benchmarks/`.
- **CI** (hosted runners, no GPU): headless Chromium with software rendering, tracking
  GPU-independent costs (layout time, draw-call count, CPU time per frame), failing on >10%
  regression against their own baseline (`QA-007`), not on absolute 60 fps.
- **Browsers:** full support for the current and previous majors of Chrome and Edge; supported
  for the current and previous Firefox (plus ESR) and Safari, using the main-thread canvas
  fallback where worker WebGL is missing; no WebGL2 → "unsupported browser" message.

### 4.9 Versions, deployment, caching
- Studio web app and BFF ship in **one image, released with the server at the same version**.
  The API stays additive (`buf breaking`, `SRV-000`); Studio refuses a server older than it
  expects. The BFF reports versions; open tabs see "Studio was updated, reload" after autosave
  flushes.
- One container started alongside the server roles (`DEP-002`); serves static files and the
  BFF; no CDN, nothing third-party (air-gapped installs).
- Hashed assets (including CanvasKit and validator WebAssembly): one year, `immutable`,
  **Brotli precompressed at build** (no per-request compression CPU). `index.html`: `no-cache`
  (fresh CSP nonce). API responses never browser-cached. **No service worker** for now.

### 4.10 Generated clients
- Add local `protoc-gen-es` (from `@bufbuild/protoc-gen-es`, pinned in `studio/bun.lock`, run
  from `studio/node_modules/.bin`) to `proto/buf.gen.yaml`; no network, no remote plugin
  (`CI-003`). Connect-ES v2 needs only this plugin; Connect Query uses its descriptors.
- Output `studio/packages/api/src/gen/*_pb.ts`, committed; exclude `plux.internal.pkcs11.v1`
  and `plux.internal.fn.v1` (`SEC-120`).
- `make gen` runs `bun install --frozen-lockfile` before buf; the folder joins
  `go-gen-check`'s paths; SPDX headers and a `REUSE.toml` Apache-2.0 annotation.
