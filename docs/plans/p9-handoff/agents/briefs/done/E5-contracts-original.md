## Your task: P9 E5 (contracts and compiler) — `Variant` nodes, experiment bindings, flag/segment/experiment/policy documents, winner promotion (`ABT-001`, `ABT-002`, `ABT-005`, `ABT-006` compile-time parts)

Server admin, statistics and the runtime are later agents' — you deliver the contracts and the compiler they build on. Read `schema/README.md` first (how JSON Schema, FlatBuffers, generated types and conformance vectors relate), then: `docs/plans/p9.md` lines 494–520 (§5.6), the Q10–Q12 rows of §2.1, §4.3 (lines 325–334); `docs/adr/0079-*.md`; `schema/json/app.schema.json` (`flags`, lines ~395–430) and `common.schema.json` (`flagType`, `value`); how a node kind is defined in `schema/json/page.schema.json`/`component.schema.json` and encoded in `schema/fbs/sections/page.fbs`/`component.fbs` (greps); the PXL roots (`grep -rn "\"flags\"" backend/internal/pxl --include=*.go | head`); the compiler pipeline (`backend/internal/compiler/compiler.go` and `doc.go` heads; `docs/reference/compiler.md` headings); how bundles declare required features (`grep -rn "requiredFeatures\|RequiredFeature" backend/internal/compiler --include=*.go | head`).

Deliver:
1. **JSON Schema:** a `Variant` node usable wherever a node is (page and component trees): `experiment` key, `control` child plus named `variants` children; documents `segment.schema.json` (targeting rules: attribute/operator/value with all/any combinators over the attributes of plan §5.5 REL-051), `flag.schema.json` (typed flag: bool | number | string | json with an embedded JSON Schema; default; per-segment values), `experiment.schema.json` (key, scope page|subtree|prop|flow|pluginVersion, variants with weights summing to 100, layer, holdout share, targeting segment, schedule, primary and guardrail metrics, minimum sample size, salt), `policy.schema.json` (approval policy: `match` resource type/environment/action/risk attributes; `require` approver count, roles, named approvers, distinctFromAuthor, distinctTeams, stages sequential|parallel, expiry — read plan §5.3 lines 411–447 for the fields). Add schema examples/testdata the way existing schemas do; the app document's `flags` stay compatible (additive only).
2. **FlatBuffers:** a `Variant` node table (additive) carrying the experiment key and the child subtrees (control first); PXL `experiment.<key>` (assigned variant name) and `experiment.<key>.<prop>` bindings type-checked against the declared experiment; generated Go/Dart/TS code via `make gen`. A bundle containing a `Variant` declares a new required feature so older runtimes refuse it (`BND-008`).
3. **Compiler validation:** `PLX-1700` policy invalid, `PLX-1701` unknown flag type, `PLX-1702` `Variant` without a control, `PLX-1703` weights not summing to 100, `PLX-1704` segment rule invalid, `PLX-2300` experiment key unknown, `PLX-2302` variant tree over the node budget (budget from the limit registry if a node-count key exists; otherwise reuse the existing per-page node budget and say so) — each with JSON paths like existing diagnostics.
4. **Winner promotion (`ABT-005`):** a pure compiler pass `PromoteWinner(doc, experimentKey, variant)` that replaces each `Variant` of that experiment by the winner's subtree and inlines `experiment.<key>` bindings to constants; `PLX-2301` if the winner is not a variant. The promoted output must be byte-identical to compiling a document written with the winner directly (`CMP-002`) — test that.
5. Conformance vectors for the new nodes/documents in the existing vector format (so the Dart runtime agent can test against them), and golden updates through the repo's `-update` flags only where your change legitimately changes output (say which).

Tests (names carry `ABT_001`/`ABT_002`/`ABT_005`/`ABT_006`/`CMP_002`): schema accept/reject tables per document, each diagnostic code with its path, PXL binding type errors, promotion byte-identity and determinism, the required-feature declaration, fuzz seeds for the new node in the existing compiler fuzz test if one exists.
