## Your task: P9 E3 runtime half — the device side of the signed control document (`SYN-060`, `REL-060`, `REL-070`, `RT-022`)

Dart only, in `packages/plux_flutter`. The server side is merged; you implement the device against it.

**The contract (read these, nothing else server-side):** `schema/control.fbs` (the document; generated Dart reader in `packages/plux_flutter/lib/src/control/fbs/control_controlfbs_generated.dart`); `proto/plux/v1/manifest.proto` lines 20–35 and 225–260 (`GetSignedControl` request/response: signed envelope bytes, ETag/If-None-Match); `backend/internal/updatemeta/control.go` and `verify.go` (how the envelope is signed by the online `control` role delegated from root — mirror this verification in Dart); `backend/internal/push/sender.go` (grep the payload marker); plan `docs/plans/p9.md` lines 448–475 (§5.4); ADR `docs/adr/0077-*.md` (headings and decision).

**Runtime context (existing code to build on):** `lib/src/verify/update_metadata.dart` (TUF-style verifier: `MetadataVerifier`, root keys, roles, thresholds, expiry, rollback faults — add the control role here); `lib/src/sync/sync_worker.dart`, `sync_engine.dart`, `api_client.dart`, `device_auth.dart` (network, DPoP and verification off the UI isolate — keep it that way); `lib/src/core/active_release.dart` (~line 369: `control.appKillSwitch || control.killSwitches.contains(key)` — today's switches come from the manifest), `lib/src/core/plux_view.dart` (~line 179: kill-switched page fallback), `lib/src/core/fallback.dart`, `lib/src/core/config.dart` (`PluxConfig`), `lib/src/core/plux.dart` (`Plux` static API), `lib/src/telemetry/events.dart` (`control_applied` is registered as `necessary`).

Deliver:
1. **Fetch:** on app resume and every 5 minutes while in the foreground (timer injectable; none in the background), with `If-None-Match` and DPoP like the manifest call, in the sync worker; `Plux.handleSilentPush(Map<String, dynamic> payload)` triggers an immediate fetch only when the payload carries the Plux marker, ignoring anything else.
2. **Verify before parse (SEC-052):** signature chain from the pinned root to the control role, expiry, and a version strictly greater than the highest seen (persisted in the existing store) — older versions refused with `PLX-3102`, a bad signature `PLX-3100`; only then run the FlatBuffers verifier and read the document.
3. **Apply without restart:** kill switches by scope — plugin and page show their fallback (RT-022; reuse today's kill-switch path, now fed from the control document as well as the manifest); action graph, data source and function calls fail with their documented errors (grep `lib/src/errors` and `schema/errors.json` for disabled action/data source/function codes; if none fits, report it rather than inventing). When the document cannot be refreshed past its expiry, every switch it last carried stays in force (fail closed for switches only) and `PLX-3101` is reported once.
4. **Mandatory update (REL-070):** activate the named release before showing any Plux page again, behind `PluxConfig.updateScreen` (a host-supplied widget builder; default: a simple localised screen showing the message key); `PLX-3103` while pending.
5. **Forced rollback:** activate the named retained earlier release (allowed only when signed in the control document), report `PLX-3104`, emit `control_applied` with the document version and what was applied.
Tests (`[SYN-060]`, `[REL-060]`, `[REL-070]`, `[RT-022]`): tampered/expired/older/wrong-role documents refused before parsing; each switch scope with its fallback or error; fail-closed past expiry; mandatory update screen (default and custom); forced rollback; silent push trigger and marker filtering; resume and 5-minute timer with a fake clock; 304 handling. Sign fixtures in Dart tests with keys generated at test time.
