Design (fixed by the lead):
1. **Bundle:** append to `table Locale`: `data: [ubyte]` = canonical JSON of the L1 per-locale data reduced to what the app uses (all number/plural/currency data of the app's currencies, the calendars the app declares in `localisation.calendar`/`secondaryCalendar` plus gregorian, all date formats/skeletons, territory and currency display names), `flutter: [ubyte]` = canonical JSON of the Flutter widget strings for that locale, `tag_resolved: string` (the CLDR locale the data came from). 2. **Flutter strings pipeline:** `tools/cmd/flutterl10n` (stdlib) reading `<flutter-sdk>/packages/flutter_localizations/lib/src/l10n/{material,cupertino,widgets}_<locale>.arb` (SDK path from `FLUTTER_ROOT` or `which flutter`; pinned version in the Makefile), writing `schema/l10n/flutter/<locale>.json` (merged material/cupertino/widgets keys, ARB metadata dropped) for every locale that exists in both Flutter's set and `schema/l10n/cldr`; `make flutter-l10n-data` in `mk/l10n.mk`; Go embeds them like the CLDR data (`go:generate` copy into `backend/internal/l10n/flutterdata/`). 5. **CMP-032:** text fonts the theme declares are subset to the Unicode script ranges of the app's supported locales (Latin, Arabic, Ethiopic, …; ranges from a small table you add, keyed by CLDR script codes from the locale's likely-subtags/`script` — if the data lacks scripts, map per language in the table), never below full coverage of those scripts; reuse the icon-font subsetter.
6. Tests: compiler goldens (update with `-update` where outputs legitimately change), a bundle round-trip of `data`/`flutter`, PLX-1600/1613 cases, a font subset test.
