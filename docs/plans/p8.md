This plan says what P8 delivers, in what order, how each part is proved, what it leaves for later
phases, and what the maintainer decided first. Requirement statuses live only in the `Status`
column of [requirements.md](../requirements.md); where this plan says a requirement "ends `DONE`"
or "stays `WIP`", that is the target at the phase exit.

**Size.** P8 tags 22 requirements (21 `MUST`, 1 `SHOULD`). Their weight is in shared engines that
must agree byte for byte in Go and Dart (CLDR formatting, MessageFormat, four calendars), in
compiler checks, and in a translation workflow with roles and four file formats. On top of that,
the **catalogue catch-up** of D14 builds the 98 widgets that Appendix C tags P3–P5 and no phase
built (§2.3): nearly as many as the 108 descriptors that exist today. Expect P8 to be about the size of P5
and P6 together; it is planned for parallel agents (§6.2).

## 1. Goal and exit criteria

**Goal (spec §5.1, as decided in §2.1).** P8 delivers:

- **CLDR-correct formatting** of numbers, money, percentages, compact numbers, dates and times,
  and plural rules, from a pinned CLDR release, identical in the compiler (Go) and the runtime
  (Dart), with each app's locale data shipped in its own bundle (D2);
- **ICU MessageFormat** with `plural` (offset, exact matches), `selectordinal`, `select` (gender
  is `select` on a gender argument), and `number`, `date` and `time` arguments, validated at
  compile time against each key's declared arguments;
- the **launch locales** `en`, `de-DE`, `ar` (RTL) and `am-ET`, and every locale the pinned
  CLDR data covers, added without code changes;
- **four calendar systems** behind one interface — Gregorian, Ethiopian, Islamic Umm al-Qura and
  Persian (D5) — with conversion, per-app and per-field choice, the PXL `calendar` group and
  `DualCalendarDatePicker`;
- **RTL** mirroring with per-node direction overrides; the runtime following the host's locale
  and switching locale at runtime without restart (`setLocale`, `Plux.setLocale`);
- **Flutter's own widget strings** (Material, Cupertino, Widgets) in every app locale without
  `flutter_localizations` (D3);
- **missing-translation fallback** along a chain, reported in development and in telemetry (D8);
- the **translation workflow** on the server and the CLI: per-key status in the translations
  document (D7), the `translator` role and `translations.approve` (D6), import and export as XLIFF
  2.0, ARB, JSON and CSV, `plux l10n pull/push/extract/status/export/import`, unused and
  over-long keys, pseudo-locales, the option to ship only approved translations, and a release
  localisation report;
- **accessibility at publish:** accessible names, alternative text, contrast in every theme, touch
  targets, fixed-height text, focus order, grouping, headings and live regions; waivers with
  justification; the setting `accessibilityBlocksPublish` (D9, D10); an accessibility report per
  release, exportable as JSON and HTML;
- **accessibility at run time:** correct semantics on every widget, minimum touch targets, the
  platform's reduce-motion, bold-text, high-contrast and screen-reader settings honoured and
  exposed to PXL;
- **golden tests** per device frame, locale, theme and text scale: `plux golden`, server-held
  baselines with approval, and an optional publish gate (D11);
- the **catalogue catch-up**: every Appendix C widget tagged P3–P5 that has no descriptor today,
  built fully — descriptor, builder, widget tests, goldens in light, dark, RTL and 200% text, a
  screen-reader script (`WGT-020`) — plus a policy check that keeps Appendix C, Appendix D and the
  registries in agreement (D14);
- **reference apps** in all four launch locales (D15).

**Exit criteria.**

1. The spec's criterion: one plugin (Plux Bank's `banking`) runs in `en`, `de-DE`, `ar` and
   `am-ET`, mirrored in `ar`, with Ethiopian dates in `am-ET` and Hijri dates beside Gregorian in
   `ar`; the publish-time accessibility checks pass on Plux Bank, Plux Express and the starter
   under the `strict` profile with no unwaived error.
2. Definition of Done (spec §5.3) DoD-1 to DoD-9 holds, with the `WIP` items of §3.2. DoD-6 for P8
   is the threat-model delta for the translation workflow (untrusted import files, the translator
   role, waivers, golden uploads) and the MASVS/ASVS checks it touches.
3. The golden suite of every reference app passes in CI on the canonical Linux renderer in all
   launch locales, light and dark, text scale 1.0 and 2.0, with no unapproved difference.
4. `make catalogue-check` passes: every Appendix C widget and Appendix D action tagged P0–P8 has
   a descriptor and a runtime builder or handler (§5.12).
5. The core package stays within `RT-061`'s budgets, and no P3–P7 benchmark regresses beyond the
   A/B gate; locale data per locale is measured and recorded (§7).
6. Every milestone passes the exit gate (§11).

## 2. Decisions

### 2.1 P8 decisions (maintainer, 2026-10-16)

| # | Decision |
|---|---|
| **D1** | **Studio and Dev-app parts.** P8 builds the engines behind `I18N-007` (extraction, unused keys, key metadata), `I18N-010` (pseudo-locales) and `A11Y-005` (text scale): in the compiler, the CLI, the server and the golden tests. The Studio and Dev-app surfaces are built in P10 and P11 (`STU-058`, `STU-111`, `DEV-011`, `DEV-034`). The requirements are **not split**: `I18N-007`, `I18N-010` and `A11Y-005` stay `WIP` at the P8 exit and end `DONE` in P10/P11. |
| **D2** | **CLDR data:** derived from a pinned CLDR release (the `cldr-json` packages) by a standard-library generator in `tools/`, as ADR-0047 does for libphonenumber; the derived per-locale data is committed and regenerated with `make gen`. The compiler embeds the data of the app's supported locales into the app bundle; the runtime carries only the engines. No `intl`, no `x/text` formatting. |
| **D3** | **Flutter's widget strings without `flutter_localizations`:** the Material, Cupertino and Widgets strings come from the pinned Flutter SDK's own ARB files, derived like the CLDR data, packed per app locale into the app bundle, and served by `plux_flutter`'s own `MaterialLocalizations`, `CupertinoLocalizations` and `WidgetsLocalizations`, which format dates and numbers with the CLDR engine. A hand-written subset for `am`, `ar` and `de` was rejected: `I18N-002` requires any locale without code changes. |
| **D4** | **Digits:** Latin digits by default in every locale; native digits (a decimal CLDR numbering system such as `arab`) opt in per app and per locale. Ge'ez numerals (non-positional) are out of scope. |
| **D5** | **Calendars:** Gregorian, Ethiopian (Amete Mihret, Amete Alem before year 1), **Islamic Umm al-Qura** (month lengths from a pinned table; tabular Islamic arithmetic outside the table's range, flagged) and **Persian** (Solar Hijri, arithmetic) — all four in P8, behind one calendar-system interface. Islamic banking shows Hijri dates beside Gregorian ones and reckons Zakat by the Hijri year. |
| **D6** | **Translator role and permissions:** new permissions `translations.edit` and `translations.approve`; a built-in `translator` role (read the app, edit translations only); `translations.approve` for `owner` and `admin`. An app setting `localisation.requireApprovedTranslations` leaves unapproved translations out of a release: they fall back along the chain and are listed in the release's localisation report; the release is not refused. P9's custom roles (`GOV-002`) build on these permissions. |
| **D7** | **Translation status lives in the translations document**, one status per key (`new`, `translated`, `reviewed`, `approved`), mapped to XLIFF 2.0 `state` (`initial`, `translated`, `reviewed`, `final`), so it travels with a project folder that teams keep in their own git repositories (`plux pull`/`plux publish`) and with import and export. The server enforces who may change a status. |
| **D8** | **Missing translations** are reported through the existing runtime telemetry as a sampled `l10n_missing` event (Appendix G.2) and in development logs; dashboards arrive with P9's telemetry ingestion. Documented in spec §17, Appendix G and the localisation guide. |
| **D9** | **`accessibilityBlocksPublish`**, a security setting: `standard` off, `strict` and `maximum` on. When on, a publish is refused on any unwaived accessibility **error**: no accessible name on an interactive node; no alternative text and no `decorative` flag on an image; contrast below 4.5:1 (normal text) or 3:1 (large text, UI components) in the light, dark or high-contrast theme; a fixed touch target below 44 × 44, or below 48 × 48 when the release targets Android; a broken focus order, heading or live-region declaration. `A11Y-003` and `A11Y-004` take `A11Y-002`'s severity: errors under `strict` and `maximum`, warnings otherwise. Warnings never block (fixed-height text; colours unknown until run time, reported as "not checked"). |
| **D10** | **Waivers and the report:** a waiver is declared in the page or on the node, names one check and carries a justification; under `maximum` a waiver is accepted only when its author holds `a11y.waive` (the stand-in for P9's approvals). The accessibility report is stored with each release and exported as JSON and standalone HTML through the API and the CLI. |
| **D11** | **Golden tests:** `plux golden` renders pages with the real runtime in a generated Flutter test harness (ADR-0052's `plux test` harness), on Linux as the canonical renderer; baselines are stored on the server per plugin, approved with `goldens.approve`; an optional app setting `goldens.blockPublish` refuses a publish whose golden run for the exact bundle hashes shows unapproved differences; a new Linux `goldens` CI job. |
| **D12** | **Fonts:** pinned Noto Sans, Noto Naskh Arabic and Noto Sans Ethiopic (OFL-1.1), vendored with SHA-256, used by the golden harness and tests only, never shipped in an app. On phones the system fonts render (Noto on Android, Kefa on iOS) unless the theme declares fonts. |
| **D13** | **Screen readers:** `QA-011` is reworded: CI runs automated semantics checks for every Layer 1 and Layer 2 widget, and scripted passes over the platform accessibility tree for the reference apps on the emulators and simulators (UiAutomator on Android, XCUITest on iOS); live TalkBack and VoiceOver passes join the real-device checklist. `A11Y-001` and `QA-011` can end `DONE`. |
| **D14** | **Catalogue catch-up:** the locale-bearing Layer 2 components come first; then **every** Appendix C widget tagged P3–P5 with no descriptor is built **fully** in a catch-up milestone of P8 (§2.3, §5.12). A policy check keeps Appendix C and D in agreement with the registries from now on. The P13 payment widgets stay in P13. |
| **D15** | **Reference-app locales:** Plux Bank and Plux Express both ship `en`, `de-DE`, `ar` and `am-ET`; the starter ships `en` and `ar`. Arabic and Amharic texts are drafted by agents and marked `translated`, not `reviewed`, until a native speaker reviews them; that review is a checklist item. |
| **D16** | **`golang.org/x/text`** gets its missing row in `dependencies.md`: imported by `backend/internal/schema/validate.go` since P1 (`b0b8dae`, #4) for the validator's messages, never used for formatting. |
| **D17** | **Process:** as P7 (plan p7 §2.4): one branch `feat/phase-8`; milestones back to back; CI, the long end-to-end runs, benchmarks and most `make` gates once, centrally, at the end; agents in their own worktrees from briefs; the lead plans, reviews and integrates; agents commit on agent branches, the lead merges into `feat/phase-8` and pushes it. |

### 2.2 Answers given while planning (maintainer, 2026-10-16)

- Translations are **central per app**: one key catalogue (`translations/keys.json`) and one file
  per locale, saved as app-level documents. The **app bundle** carries them, one `l10n` section
  per locale (`sections.go` calls `localeSections` on the app bundle only; plugin bundles carry
  no messages). P8 keeps that and adds each locale's data (E7) to the same sections. *Corrected
  2026-10-16: an earlier answer in the planning session said every plugin bundle carried all
  messages; the code shows it does not.*
- Plux Express gains `am-ET` (D15).

**E4 — Settings.** `accessibilityBlocksPublish` in `schema/security/settings.json` (bool, tighter
`true`; `standard` false, `strict` and `maximum` true; does not travel to the device; P8;
`A11Y-002`, `A11Y-008`). App-document settings (not security settings):
`localisation.calendar` (`gregorian` default), `localisation.secondaryCalendar` (none default),
`localisation.numberingSystem` (per locale, `latn` default, D4),
`localisation.requireApprovedTranslations` (false), `localisation.pseudoLocales` (false; refused
in production environments, `PLX-1614`), `goldens.blockPublish` (false) and `goldens.matrix`
(frames, themes, text scales, locales).

**E5 — Permissions and roles (`auth/rbac.go`, ADR-0068).** New permissions
`translations.edit`, `translations.approve`, `a11y.waive`, `goldens.approve`. Grants: `owner` all;
`admin` all four; `developer` `translations.edit`; `viewer` none; new role **`translator`**:
`organization.read`, `app.read`, `plugin.read`, `translations.edit`. Step-up (`NeedsSecondFactor`):
`translations.approve`, `a11y.waive`, `goldens.approve`. `translations.edit` alone lets a caller
save only documents of kind `translations`, and only messages and states (`PLX-8093` otherwise);
Today translations are app-level documents, saved only with `app.manage` (`document.go`
`editPermission`) under the app-level editing lock (`SRV-042`), so developers cannot edit them and
a translator would block the theme and `app.json`. P8 gives `translations` documents their **own
lock per locale** (an additive refinement of `SRV-042`, spec E1) and accepts saves from
`app.manage` or `translations.edit`. Setting or keeping a changed message at `approved` needs
`translations.approve` (`PLX-8092`); a text change by anyone without it resets that key's state to
`translated`.

**E6 — Contracts.** Additive; every incompatible change is called out in the pull request (C6 of
plan p7).

- **Documents.** `translations`: `states` (key ID → status). `translationKeys`: `screenshot`

  `direction` (`ltr`, `rtl`, `inherit`), `localeOverrides` (locale → props, `I18N-012`),

  `translatable` on string props (drives extraction and `PLX-1609`), `minTarget` on interactive

- **Bundle.** The app bundle's `l10n` sections gain `LocaleData` (plural and ordinal rules

  `Message`s; plugin bundles stay without messages (§2.2). Message
  texts are stored pre-parsed (a compact AST) so the device never parses MessageFormat on the UI
  isolate. New `Node` fields for direction, locale override layers (`BND-016` already encodes
  override layers) and semantics; a `Locale.calendars` list.
- **Proto.** `LocalisationService` (`ExportTranslations`, `ImportTranslations`, `GetStatus`,
  `SetStates`); `ReleaseService.GetReport` (kind `accessibility` or `localisation`, format `json`

- **Actions.** `setLocale` and `setThemeMode` get handlers; `announce` (new id, P8).
- **Widgets.** 99 new descriptors with new permanent IDs (D14, `DualCalendarDatePicker`), the

**E7 — Locale data pipeline (ADR-0066).**

- `make cldr-data` downloads the pinned `cldr-json` release (version and SHA-256 in
  `mk/l10n.mk`, like `phone-metadata`), and `tools/cmd/cldrdata` (standard library only) derives
  `schema/l10n/cldr/<locale>.json` for the A2 set: plural and ordinal rules, decimal and percent
  and currency and compact patterns, symbols per numbering system, currency symbols, narrow
  symbols and digits (ISO 4217 data from CLDR's supplemental), date and time patterns and
  available skeletons, names per calendar (gregorian, ethiopic, islamic-umalqura, persian), layout
  direction, and parent locales for fallback. The source archive is not committed; derived files
  are, each well under the 500 KB hook limit.
- `make flutter-l10n-data` derives `schema/l10n/flutter/<locale>.json` from the pinned Flutter
  SDK's `flutter_localizations` ARB files (read from the SDK on disk, not depended on).
- `make gen` turns both into Go and Dart lookup code for the conformance tests and the compiler;
  the runtime reads only what the app bundle carries.
- Locale resolution (Go and Dart identical): BCP 47 canonicalisation, CLDR parent chain
  (`de-AT` → `de` → `root`), then the app's default locale; the release resolves each supported
  locale to its data once, at compile time.
- Determinism: derived files are sorted and canonical (RFC 8785); regeneration from the same pin
  is byte-identical (`CMP-002`).

**E8 — Calendars (ADR-0067).** One interface in Go and Dart: `fromJdn`/`toJdn` (Julian day
number), `monthsInYear`, `daysInMonth`, `eraOf`, `isLeap`, `epoch`. Gregorian (proleptic),
Ethiopian (Amete Mihret; Amete Alem before year 1), Islamic Umm al-Qura (month lengths for
1300–1600 AH from a pinned ICU release, Unicode-3.0 licence, the table committed as vectors;
outside it, tabular Islamic arithmetic and `PLX-1615`), Persian (the arithmetic of the pinned
ICU release). PXL `toCalendar(date, system)` and `fromCalendar(parts, system)` become real;
`format.date` takes the field's or app's calendar. Conformance vectors: 2,000 dates per calendar
across the table range and the edge years, generated once from ICU and committed.

**E9 — MessageFormat (ADR-0066).** One parser in Go (the compiler validates and pre-parses into
the bundle's AST) and one evaluator in Go and Dart (Go for the conformance tests, the server's
pseudo-locales and the CLI's previews). Arguments are typed by the key's declared `args`; a
message using an undeclared argument, a plural category the locale lacks, or no `other` branch
is refused (`PLX-1601`–`1605`). `render/messages.dart` is replaced by the AST evaluator.

**E10 — Accessibility checks (ADR-0069).** Compiler stage `policy` gains:

- **Names (`A11Y-002`):** interactive nodes (descriptor `accessibility.interactive`) need a
  semantics label or text in their subtree (existing `PLX-1401`, now with D9's severity); images
  need `semanticLabel`/`semantics.label` or `decorative`/`excludeFromSemantics` (`PLX-1402`).
- **Contrast (`A11Y-003`):** for every text node and every UI component boundary (button fill,
  input outline, icon), the compiler resolves foreground and background from props, token
  references and the theme's role pairs in the light, dark and high-contrast token sets, walking
  ancestors for the nearest opaque background; WCAG 2.2 relative luminance; large text is
  ≥ 24 px, or ≥ 18.66 px bold. A colour the compiler cannot know (an expression, an image
  background) is listed as "not checked" (`PLX-1409`).
- **Targets (`A11Y-004`):** explicit sizes on interactive nodes and their tight constraints from
  ancestors against 44 × 44 and, for Android targets, 48 × 48.
- **Text scale (`A11Y-005`, `SHOULD` part):** a text node under a fixed-height ancestor
  (`PLX-1405`).
- **Structure (`A11Y-006`):** `focusOrder` unique and dense within a group; heading levels not
  skipping more than one level within a page; a `liveRegion` whose content is constant
  (`PLX-1408`).
- Waivers (`PLX-1410`, `1411`) and the report (`A11Y-008`): every check run, its scope and result,
  every violation with node path and severity, every waiver with author, justification and
  release; JSON (schema in `schema/json/a11y-report.schema.json`) and HTML rendered from it.

**E11 — Golden tests (ADR-0070).** `plux golden run|approve|status` compiles the project, writes
the harness (`plux test`'s, ADR-0052), renders each case with the real runtime under `flutter
test` on the host's Flutter SDK, with the vendored fonts (D12) and the pseudo-locales, and
compares PNGs pixel by pixel (exact on Linux; on other systems a tolerance and the run is marked
"non-canonical", which the gate never accepts). Frames come from `schema/goldens/frames.json`
(phone small 360 × 640 @2, Pixel 8 412 × 915 @2.625, iPhone 15 393 × 852 @3, tablet 820 × 1180 @2,
each with its platform style). A case renders with all data sources mocked (`TST-004` mocks) and
the clock frozen. Runs upload results (bundle hashes, case IDs, image SHA-256s, the differing
images) to `GoldenService`; approving stores new baselines. The gate (`goldens.blockPublish`)
compares the release's plugin bundle hashes with the latest canonical run; determinism
(`CMP-002`) makes the local compile's hashes the server's.

**E12 — Runtime (ADR-0066, ADR-0069).** A `LocaleController` (Riverpod) holds the effective locale:
`PluxConfig.locale`, `Plux.setLocale`, the `setLocale` action, or the host's locale; switching
rebuilds Plux subtrees under a new `Localizations` and `Directionality` without restarting the
engine or losing page state. Formatting, plural rules and calendars read the app bundle's
`LocaleData`. Missing keys fall back along the chain; release builds never show a key
(`I18N-006`); development builds mark fallbacks visibly. Semantics: every builder passes role,
label, value, state and actions; `focusOrder` maps to `OrdinalSortKey` inside a
`FocusTraversalGroup`; `group` to a semantics container; `headingLevel` to `Semantics.headingLevel`;
`announce` to `SemanticsService.sendAnnouncement` with the view and the text direction
(`announce` is deprecated in the pinned Flutter 3.47.5; `Semantics.headingLevel`, the
`flutter_localizations` ARB files and the `flutter_test` guidelines named in §5.7 were checked
against the same SDK on 2026-10-16). Settings
(`MediaQuery.disableAnimations`, `boldText`, `highContrast`, `accessibleNavigation`) feed the
renderer and the `device` root. Minimum targets: Material's padded tap targets, Cupertino's 44 pt.

**E13 — Catalogue catch-up (ADR-0071).**

- **Layer 1 rule:** each widget mirrors its Flutter class (coverage table), with Flutter's
  controllers mapped to state as the coverage table already does ("controller→state"): `TabBar`
  and `TabBarView` share an `index` bound to a state key; `ReorderableListView` emits
  `onReorder` and writes the bound list; `PopupMenuButton`, `MenuAnchor`, `SearchAnchor` and
  `Autocomplete` take items from a list binding or a data source; `Draggable` and `DragTarget`
  carry a typed payload; `RefreshIndicator`'s `onRefresh` runs a graph and completes when it ends.
- **Animation widgets:** the `Animated*` widgets are Flutter's implicit widgets with
  `duration`, `curve` and `onEnd`, so they coexist with node-level implicit animation
  (`ANI-001`); `Hero` takes `tag` (the same tags as node-level `hero`); `Timeline` plays a page
  timeline over its subtree (`timeline`, `autoplay`, `repeat`); the four `*Transition` widgets bind
  their animated value to a timeline track; all follow reduce motion (`ANI-007`).
- **Structural:** `DataScope` binds one data source and exposes `loading`, `empty`, `error` and
  `success` slots (the page-level `dataSources` stay); `NativeSlot` names a catalogue slot
  explicitly (`name` prop) — equivalent to using the slot's name as the node type, which keeps
  working.
- **Layer 2 rule (`WGT-020`):** built in Dart from Layer 1, the theme and runtime services; each
  has a descriptor, widget tests, goldens in light, dark, RTL and 200% text, and a screen-reader
  script. Money and number widgets use the CLDR engine and the PXL `decimal`/`money` types;
  `PhoneInput` the `pxl.phone.v1` table; `IbanInput` the IBAN table; `CountryPicker` and
  `CurrencyPicker` CLDR's territory and currency names in the current locale; `FileUploader` the
  data layer's transfers (ADR-0048) and `plux_media`'s picker; `LiveEtaCard` a stream data source;
  `InfiniteList` a paginated data source (`WGT-012`).
- **Package widgets (`RT-060`, ADR-0051):** a package registers its widget builders with a new
  `PluxWidgetPackage` (additive public API beside `PluxDevicePackage`) passed in
  `PluxConfig.widgetPackages`; descriptors stay in `schema/widgets/layer2` with a `package` field;
  a node whose package is missing renders the node fallback and reports `PLX-4403`
  `WIDGET_PACKAGE_MISSING` (new, beside `PLX-5401` for device packages); publishing warns when a targeted host build lacks the package (ADR-0051).
  `PluxLottie.slots` and the Rive slot stay, deprecated, for one minor release.
- **Policy check (`make catalogue-check`, `tools/`):** reads Appendix C and D from the spec and
  fails when a widget or action whose phase is at or before the current phase has no descriptor,
  no runtime builder or handler, or a descriptor phase that disagrees with the appendix.

**E14 — Pinned data, sources and tools.** CLDR `cldr-json` (Unicode-3.0) at the release fixed in
L1; Flutter's ARB files at the pinned SDK (3.47.5, BSD-3-Clause); the Umm al-Qura table and the
calendar vectors from the pinned ICU release (Unicode-3.0); Noto fonts at a pinned
`notofonts` release (OFL-1.1). Each is recorded in `dependencies.md` ("Vendored data") and
`REUSE.toml`.

## 5. Architecture

### 5.0 Starting point (surveyed 2026-10-16)

- **Documents:** `translations` (locale, messages by key ID) and `translationKeys` (key, ID,
  description, `maxLength`, `args`) exist; `$t` references with `args` (`SCH-011`); `app`
  declares `defaultLocale` and `supportedLocales`.
- **Compiler:** indexes keys, resolves `$t` (`EdgeUsesTranslation`), encodes one `l10n` section per
  locale with every message (`sections.go` `localeSections`); `PLX-1401` warns on missing names
  (`policy.go`).
- **Runtime:** `render/messages.dart` formats simple arguments, `select` and `plural` with the
  English rule only; the renderer reads `Plux.setLocale`/`PluxConfig.locale`/the host locale,
  `disableAnimations` and `highContrast`; `Semantics` built from `label`, `hint`, `value`, `header`,
  `button`, `liveRegion`, `excludeSemantics`; icons mirror in RTL; `textDirection` is hard-coded
  `ltr` in two decoding paths (`renderer.dart:1664`, `decoding.dart:45`).
- **PXL:** `format.iban` only; `format.number|money|date|percent|compact|phone`, `t`, `plural`,
  `toCalendar`, `fromCalendar` are declared in `schema/pxl/stdlib.json` and unimplemented.
- **Server:** four roles; plugin documents saved with `plugin.edit`, app-level documents —
  translations among them — with `app.manage`, each under its draft's lock; no localisation API; `plux test` writes a Flutter harness (ADR-0052).
- **Widgets:** 99 Layer 1 and 9 Layer 2 descriptors; goldens in `plux_flutter/test/render/goldens`.
- **Studio:** two packages (`brand`, `schema`); no Dev app.

### 5.1 Locale data and formatting (L1) — ADR-0066

- `tools/cmd/cldrdata`, `tools/cmd/flutterl10n`, `schema/l10n/`, `mk/l10n.mk` (E7).
- `backend/internal/l10n/` (Apache-2.0, a pure library used by the compiler, the server and the
  CLI): locale resolution, plural rules, number formatting (grouping, minimum and maximum
  fraction digits, rounding half-even for display, currency digits from ISO 4217, accounting
  pattern, compact short), date and time formatting from skeletons, calendar-aware.
- `packages/plux_flutter/lib/src/l10n/`: the same engine in Dart over the bundle's `LocaleData`;
  no allocation per frame for cached formatters.
- Conformance vectors `schema/testdata/l10n/{numbers,money,dates,plurals}.json`, generated from
  the pinned CLDR with ICU's expected outputs for the A2 set's launch locales and a sample of 20
  other locales; Go and Dart run them (`QA-003`).

### 5.2 MessageFormat and PXL groups (L2) — ADR-0066

- Parser and AST (`backend/internal/l10n/mf`), bundle encoding of the AST, Dart evaluator.
- PXL `format.*` (except `phone`, which reads `pxl.phone.v1`), `t`, `plural`, wired in Go and Dart
  VMs with the feature flags `pxl.format.v1` and `pxl.l10n.v1`; `PXL-007` vectors.
- Compiler validation of every message against its key's `args` and the locale's plural
  categories; `maxLength` checked against the default-locale rendering with sample arguments.

### 5.3 Calendars (L3) — ADR-0067

E8 in Go (`backend/internal/l10n/calendar`) and Dart (`lib/src/l10n/calendar/`); `pxl.calendar.v1`;
`DualCalendarDatePicker` (Layer 2): a primary and an optional secondary calendar, month grid in the
chosen calendar with the other's day numbers, era handling, min and max dates, keyboard and
screen-reader navigation; `CalendarDatePicker`, `CupertinoDatePicker` and `format.date` take the
app's or field's calendar.

### 5.4 Runtime localisation (L4)

E12: `LocaleController`, `setLocale` and `setThemeMode` handlers, `Plux.setLocale` unchanged,
RTL through `Directionality` (and the two hard-coded `ltr` paths fixed), node `direction`
overrides, `localeOverrides` applied as override layers, per-locale assets, the Flutter widget
strings served from the bundle (D3), the runtime's own strings (`ACT-020`, secure widgets, the
fallback page) as a runtime catalogue, native digits (D4), fallback and `l10n_missing` telemetry,
the `device` root's new fields, `CMP-032` font subsetting in the compiler.

### 5.5 Translation workflow (L5) — ADR-0068

- **Server:** `LocalisationService`; E5's permission checks in `DocumentService` for
  `translations` documents (a `translator` save that changes anything but messages and states is
  refused); state transitions; `requireApprovedTranslations` in the compile; the localisation
  report stored with the release.
- **Formats (`backend/internal/l10n/xchange`):** XLIFF 2.0 (`<file>` per plugin scope, `<unit
  id>` = key ID, `<segment state>` = D7's mapping, `<notes>` with description and `maxLength`),
  ARB (key name, `@key` metadata with description, placeholders), JSON (the Plux translations
  document itself), CSV (RFC 4180: key ID, key, source, target, state, description, max length).
  Every importer is size-bounded (`translation.importSize`), refuses DTDs and entities in XML,
  never resolves external references, and is fuzzed. An import whose source text changed since
  export marks the key `translated` and warns (`PLX-1622`).
- **CLI:** `plux l10n pull` and `push` (`CLI-003`), `export --format xliff|arb|json|csv
  [--locale]`, `import`, `status` (coverage per locale and plugin), `extract` (rewrites
  `translatable` literal props into new keys with UUIDv7 IDs, reviewable as a diff), `pseudo`
  (writes `en-XA` and `ar-XB` for previews).
- **Compiler:** unused keys (`PLX-1608`), literal text in `translatable` props (`PLX-1609`),
  missing translations (`PLX-1606`), pseudo-locales `en-XA`
  (accented, expanded by 35%, bracketed) and `ar-XB` (RTL, bidi-wrapped) generated from the
  default locale when `localisation.pseudoLocales` is on outside production.

### 5.6 Accessibility at publish (L6) — ADR-0069

E10 in `backend/internal/compiler/a11y*.go`, run in the `policy` stage; severities from the
effective profile; `accessibilityBlocksPublish` read by the publish pipeline (`PLX-3060`); waivers
validated (`a11y.waive` under `maximum` checked by the server against the saving principal,
recorded in the audit log); the report stored with the release and served by `GetReport` and
`plux release report --kind accessibility --format json|html`.

### 5.7 Accessibility at run time (L7) — ADR-0069

Semantics on every builder (role, label, value, state flags, actions: tap, long press, increase,
decrease, scroll, dismiss); `focusOrder`, `group`, `headingLevel`; `announce`; minimum targets;
settings and the `device` root; a shared test helper that asserts each widget's semantics node and
Flutter's `meetsGuideline` (`androidTapTargetGuideline`, `iOSTapTargetGuideline`,
`labeledTapTargetGuideline`, `textContrastGuideline`) for every descriptor in every golden variant
(`QA-011`'s automated part). Accessibility-tree passes: the existing Android and iOS end-to-end
flows of the reference apps gain steps that walk the tree with UiAutomator and XCUITest, assert
labels, roles and order of each page, and run in `ar` once (D13).

### 5.8 Golden tests (L8) — ADR-0070

E11: `backend/internal/plxtest/golden*.go` (harness generation, case matrix, PNG comparison),
`plux golden`, `GoldenService` and its storage (object storage under the plugin, rows in
PostgreSQL, row-level security like every tenant table), `goldens.approve`, the gate in the
publish pipeline (`PLX-3061`, `3062`), the vendored fonts, the `goldens` CI job running the
reference apps' suites.

### 5.9 Catalogue catch-up (K1–K3) — ADR-0071

E13. Each widget is one unit of work: descriptor (props with IDs and Flutter mapping), builder,
widget tests, goldens (light, dark, RTL, 200%), semantics test, screen-reader script, coverage
table, Appendix C check. Work is split by Appendix C group so agents do not share files: builders
go into new files per group (`builders/navigation.dart`, `builders/animation.dart`,
`builders/menus.dart`, `layer2/money.dart`, `layer2/commerce.dart`, …), registered in one generated
table.

### 5.10 Reference apps (L9)

Plux Bank: `de-DE`, `ar`, `am-ET` beside `en`; `MoneyText`, `AmountInput`, `TransactionListItem`,
`AccountCard`, `DualCalendarDatePicker` (Gregorian with Hijri in `ar`, Ethiopian in `am-ET`), an
`announce` on transfer errors; `strict` checks pass. Plux Express: the four locales;
`ProductCard`, `PriceTag`, `QuantityStepper`, `CartSummary`, `Carousel`, `StatusTimeline`,
`LiveEtaCard`, `OrderTrackerMap` if A1 is approved in time, `RatingInput`. Starter: `en` and `ar`.
Each app's golden suite and accessibility-tree pass; Plux Express's `TabBar`/`NavigationBar` shell.

### 5.11 Observability

`l10n_missing` (G.2); Prometheus `plux_translation_imports_total{format,result}`,
`plux_golden_runs_total{result}`, `plux_publish_blocked_total{reason}` (G.1).

### 5.12 Keeping the catalogue honest

`make catalogue-check` (E13) joins `make check` and CI's lint job; it would have caught §2.3 in P3.

### 5.13 Runbooks (L10)

Listed here so L10 does not miss them: a locale shows keys or the default language (fallbacks,
`l10n_missing`, the release's localisation report); a translation import is refused; a publish is
blocked by accessibility or goldens (reading the report, waiving, approving); golden runs are
non-canonical; a calendar shows the wrong day (table range, `PLX-1615`).

## 10. Risks

| Risk | Mitigation |
|---|---|
| Go and Dart formatting drift | One generated data source; shared vectors from ICU's outputs; the compiler pre-parses messages so the device evaluates an AST, not text |
| The catch-up is large and touches the core package's size | Split by Appendix C group with disjoint files; size measured each milestone; heavy components can move to optional packages (§2.4) |
| Umm al-Qura differs from local moon sighting | The table is the Saudi civil calendar, documented as such; ±1-day adjustment per app is a later option, recorded in ADR-0067 |
| Contrast checks give false results | Unknown colours are "not checked", never guessed; hand-computed vectors; waivers with justification |
| Goldens differ by machine | Linux is canonical; other systems are non-canonical and never satisfy the gate; fonts are vendored |
| Untrusted translation files | Size limits, no DTDs or entities, no external references, fuzzing, permission checks on import |
| Agent-drafted Arabic and Amharic are wrong | Marked `translated`, never `approved`; native-speaker review on the device checklist (D15) |
| P8 runs long | Waves of §6.2; the checkpoint at L9; K3 can finish after L9 without blocking the exit criterion's plugin |

## 11. Process

- **Branch and pull request:** one branch, `feat/phase-8`, and one pull request at the phase exit,
  with the L9 checkpoint reviewed on the branch (D17).
- **Agents:** §6.2; the lead merges, reviews every merge, and runs all gates centrally.
- **Exit gate** (the milestone gate of P3–P6, run once at the end as in P7):
  1. every `make` gate passes locally, judged by its exit code, not its output;
  2. the end-to-end gate tests pass at least 40 times with the race detector, and every
     intermittent failure is root-caused;
  3. a dispatched CI run is green in every job, including `goldens`;
  4. every open item is fixed or put to the maintainer;
  5. the hand-off note and the report say what was verified and how.
- **Stops for the maintainer** (AGENTS §7), already known: L0's spec changes and ADRs; A1 and A2;
  the new CI job; the new limits' defaults; coverage floors of new packages; E5's roles and
  permissions; `accessibilityBlocksPublish`; the size gate if it trips.
- **Work log:** `docs/WORKLOG.md` tracks the current wave and milestone. This plan changes only by
  dated decisions recorded in §2.
