# Issue register (maintainer, 2026-11-15)

Every issue the maintainer reported while walking the Apply Register checklist (sections A–B2), plus the open
bugs of [next-steps.md](next-steps.md) §2.1. Each is root-caused, fixed and tested in turn; the **State** column is
updated as each lands. After all are fixed, the checklist (`docs/plans/apply-register/README.md`) is validated
section by section and the findings are put to the maintainer before they continue.

States: `open` · `analysing` · `fixed` (with the commit) · `decision` (waiting for the maintainer).

## Data integrity and saving (first)

| ID | Issue | State |
|---|---|---|
| D1 | Edits are not persisted and revert: a route changed in a plugin comes back after reopening; `PutDocument` answers 409 repeatedly (seen while dragging a renamed plugin, which snaps back to the centre). | fixed |
| D2 | Duplicating a plugin copies keys that must be unique (routes), so the copy and the original clash at once. Duplicate must follow the usual rules: unique keys get a fresh value, and nothing invalid is created. | fixed |
| D3 | Creating, duplicating, deleting or restoring a plugin does not update `app.json` `plugins`, so the app reports PLX-1020 (STU-034 is broken). | fixed |
| D4 | Studio throws refusal reasons away (106 `catch {}`; the admin save helper): step-up (PLX-6200/6201) is never asked for, every refusal reads "The change was not saved". | fixed |
