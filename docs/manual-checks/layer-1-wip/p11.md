- **Needs:** R-STACK, R-ADMIN, R-L1-SR
- **Do:** sign in to <http://localhost:8081> with each screen reader and work through the checklist
  of `docs/engineering/studio-development.md` §15.1 (landmarks, every area route, both canvases,
  dialogs, toasts, tables, charts, form errors, 200% zoom and forced colours).
- **Expect:** every item ticks on both set-ups.
- **Why:** WCAG 2.2 AA needs a person with a screen reader; axe and the keyboard tests
  (`studio/e2e/a11y-sweep.spec.ts`, `keyboard.spec.ts`) cover the rest (STU-011).
- **Moves to DONE when:** the ticked list, per screen reader, is recorded in the pull request or
  work log, and each failure has an issue that is fixed.
- **Result:** ☐ pass ☐ fail — notes:

### L1-STU-803 — The publish flow shows a server-rendered visual diff (STU-100)

- **Needs:** R-STUDIO on a machine with Docker; R-APP-DEMO
- **Do:**
  1. `COMPOSE_PROFILES=visual-diff make compose-up` (adds the render worker `plux-render-worker`).
  2. In Studio change a screen of `demo`, open **Publish**, go through every step: plugins with
     changes, reports, diffs, changelog, target, approval request, rollout plan.
- **Expect:** the diffs step shows before and after images of the changed screen on the standard
  devices, and the JSON diff; the release request goes to approval.
- **Why:** reviewers approve what users will see (STU-100).
- **Look at:** `docker compose -f deploy/compose/compose.yaml logs plux-render-worker`; the render
  worker has never run in the agents' container (`docs/plans/p11-handoff/open.md`).
- **Moves to DONE when:** this passes and CI's `studio-image-repro` job (Studio and render worker images) is green.
- **Result:** ☐ pass ☐ fail — notes:
