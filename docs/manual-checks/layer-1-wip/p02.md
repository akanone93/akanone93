- **Needs:** S-1, Docker
- **Do:**
  1. `make compose-up`
  2. `docker compose -f deploy/compose/compose.yaml ps --format '{{.Service}} {{.Status}}'`
  3. `COMPOSE_PROFILES=keycloak make compose-up`, then step 2 again.
- **Expect:** `plux-server`, `plux-fnrunner`, `plux-egress`, `studio`, `postgres`,
  `seaweedfs`, `valkey`, `otel-collector`, `prometheus`, `grafana` healthy; step 3 adds
  `keycloak` (the `ollama` profile works the same way).
- **Why:** Studio joined the stack in P11 but no Docker run of it was recorded (DEP-002).
- **Moves to DONE when:** this passes and the CI **compose** job is green on `main`.
- **Result:** ☐ pass ☐ fail — notes:

### L1-SRV-002 — Usage against every limit, API and Studio (LIM-005)

- **Needs:** R-STACK, R-STUDIO
- **Do:**
  1. Define R-L1-API from the repository root:
     `. deploy/compose/.secrets/dev.env; pluxapi() { curl -sS --cacert deploy/compose/.secrets/ca/ca.crt "https://localhost:8080/plux.v1.$1" -H "Authorization: Bearer $PLUX_DEV_TOKEN" -H "X-Plux-Organization: $PLUX_DEV_ORGANIZATION" -H 'Content-Type: application/json' -d "$2"; }`
  2. `pluxapi AppService/ListAppLimits "{\"appId\":\"$PLUX_DEV_APP\"}"`
  3. In Studio: R-APP-DEMO's **Settings**: the usage table, then the **Plugin usage** section;
     pick one of its plugins.
- **Expect:** step 2 lists every app-scope limit with its usage; Studio shows the app's usage
  and, per plugin, the plugin-scope limits (pages, bundle size, golden bytes). Rate, timeout
  and per-request limits show no current value by design.
- **Why:** usage is measured server-side and shown per app and per plugin (LIM-005, STU-025).
- **Look at:** the `ListPluginLimits` call (PluginService) in the browser's network tab.
- **Moves to DONE when:** you confirm the limits without a current value (runtime and
  per-request limits, `plugin.assetBytes` per plugin) are acceptable as unmeasured, or name
  the ones to measure; the per-plugin view itself exists since P11 (S8.1).
- **Result:** ☐ pass ☐ fail — notes:

### L1-OPS-008 — Signed multi-arch images with SBOM and provenance (DEP-001)

- **Needs:** Docker; R-L1-TAG for steps 2–3
- **Do:**
  1. `make image-check`
  2. `docker buildx imagetools inspect ghcr.io/nightcode42/plux-server:<version>` (and `plux-studio`).
  3. `cosign verify ghcr.io/nightcode42/plux-server:<version> --certificate-oidc-issuer https://token.actions.githubusercontent.com --certificate-identity-regexp '^https://github.com/nightCode42/plux3/'`
- **Expect:** step 1 passes; `linux/amd64` and `linux/arm64`; a valid signature, and
  `cosign verify-attestation --type cyclonedx` (same flags) shows the SBOM.
- **Why:** the image jobs run only on a tag and have never run (DEP-001).
- **Moves to DONE when:** the first `backend` and `studio` Release runs are green and steps 2–3 pass.
- **Result:** ☐ pass ☐ fail — notes:
