# Layer 2 — Localisation and accessibility

You run `shop` in English, German, Arabic and Amharic, mirror it right to left, switch the language
at run time, show dates in the Ethiopian calendar, exchange translations with a translator, and read
the accessibility findings and report of a release. Guides: [localisation](../../guides/localisation.md),
[calendars](../../guides/calendars.md), [translation workflow](../../guides/translation-workflow.md),
[accessibility](../../guides/accessibility.md).

## Resources this file adds

| ID | What | Made by |
|---|---|---|
| R-L10N-XLF | `/tmp/de.xlf`, an XLIFF export of the German locale | L2-L10N-007 |
| R-A11Y-REPORT | `/tmp/a11y.html`, the accessibility report of a release | L2-L10N-018 |

### L2-L10N-001 — Four launch locales are supported

- **Needs:** R-APP, R-PROJECT
- **Do:** open `app.json` in R-PROJECT; read `defaultLocale` and `supportedLocales`.
- **Expect:** `en` as default and `de`, `ar`, `am` (written as the wizard stored them, for example `de-DE`, `am-ET`).
- **Why:** English, German, Arabic and Amharic are the launch locales (I18N-001).
- **Look at:** adding an unsupported locale code and running `plux validate` gives `PLX-1600`.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-002 — Translate every key

- **Needs:** R-APP, keys of L2-STU-030/031
- **Do:** in Studio **Localisation** give `list.title` and `list.empty` texts in `de`, `ar`, `am`; approve them.
- **Expect:** the **Heatmap** shows no missing keys for the three locales.
- **Why:** a release carries only approved text.
- **Look at:** `plux l10n status -C ~/plux-checks/shop` (after `plux export`) lists keys per locale by state.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-003 — Preview a locale on the canvas

- **Needs:** R-SCREENS
- **Do:** switch the canvas **Locale** to `de`, `ar`, `am`.
- **Expect:** the texts change; `ar` mirrors the layout; Amharic shows Ge'ez glyphs from your fonts.
- **Why:** the preview equals the device (I18N-004, STU-005).
- **Look at:** missing glyph boxes mean a missing font in **Typography** (R-FONTS).
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-004 — Run in German on the device

- **Needs:** R-DEVICE-SHOP
- **Do:** publish; set the device language to German; restart `shop`.
- **Expect:** the German texts appear without any host code.
- **Why:** the effective locale defaults to the device's (I18N-002).
- **Look at:** `PLX-4401` and an `l10n_missing` event if a key lacks a German text.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-005 — Right to left on the device

- **Needs:** R-DEVICE-SHOP
- **Do:** set the device language to Arabic; restart.
- **Expect:** the layout mirrors: start edge on the right, icons and back arrows flipped, text right-aligned.
- **Why:** layouts mirror automatically (I18N-004).
- **Look at:** numbers and Latin names stay left-to-right inside Arabic text.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-006 — Switch language at run time

- **Needs:** R-DEVICE-SHOP, a button with the `setLocale` action
- **Do:** add a button in Studio running `setLocale` with `de`; publish; type something in a field; tap the button.
- **Expect:** all texts change language at once; the field keeps its content and the screen does not reload.
- **Why:** a switch rebuilds subtrees without restarting (I18N-003).
- **Look at:** an unsupported locale is refused.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-007 — Export a locale: create R-L10N-XLF

- **Needs:** R-PROJECT
- **Do:** `plux l10n export --locale de --format xliff --out /tmp/de.xlf -C ~/plux-checks/shop`; open the file.
- **Expect:** an XLIFF with the default-locale source and the German target for each key.
- **Why:** translators use their tools.
- **Look at:** the same export is available in Studio **Export translations**.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-008 — Import a translation with a dry run

- **Needs:** R-L10N-XLF
- **Do:** change one German target in the file; `plux l10n import --locale de --dry-run /tmp/de.xlf -C ~/plux-checks/shop`; then without `--dry-run`.
- **Expect:** the dry run reports the changed key and writes nothing; the real run applies it and the key goes to *needs review* for non-reviewers.
- **Why:** imports follow the review rules.
- **Look at:** Studio **Localisation** shows the new status.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-009 — A bad import is refused

- **Needs:** R-PROJECT
- **Do:** import a file that is empty, then one with an unknown key, in Studio and by CLI.
- **Expect:** refused before anything changes, with a reason.
- **Why:** import is validated first.
- **Look at:** [translation import runbook](../../runbooks/translation-import.md).
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-010 — Pseudo-locales

- **Needs:** R-PROJECT
- **Do:** `plux l10n pseudo -C ~/plux-checks/shop`; import or preview `en-XA` and `ar-XB`.
- **Expect:** accented and expanded text, and a mirrored test locale; layout problems (clipping, fixed widths) show up.
- **Why:** find i18n bugs before translators do.
- **Look at:** the `fixedHeightText` finding (`PLX-1405`) if any text clips.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-011 — Extract literal text

- **Needs:** R-PROJECT
- **Do:** add a literal text in a page JSON; `plux l10n extract --dry-run -C ~/plux-checks/shop`; then without `--dry-run`.
- **Expect:** the literal becomes a `$t` reference and the text lands in the default locale.
- **Why:** nothing ships hard-coded (I18N-001).
- **Look at:** `git diff` of the project.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-012 — Plurals with MessageFormat

- **Needs:** R-APP
- **Do:** add key `cart.items` with `{count, plural, one {# item} other {# items}}`, in `de` and `ar` (Arabic has more plural forms); bind `count` to state; show 0, 1, 2, 11.
- **Expect:** correct forms per language; a missing required form is reported when compiling.
- **Why:** ICU MessageFormat with CLDR rules (I18N-010).
- **Look at:** the `args` declared on the key in `translations/keys.json`.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-013 — Number, money and date formats

- **Needs:** R-DEVICE-SHOP
- **Do:** show `format.money(1234.5, "EUR")` and `format.date(...)` in a text; switch locales.
- **Expect:** `1.234,50 €` in `de`, Arabic-style digits or grouping per `ar`, Ethiopic digits conventions per `am`.
- **Why:** formats come from CLDR data (I18N-011).
- **Look at:** `dev pxl` (L2-DEV-014) evaluates the same expression.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-014 — Ethiopian calendar

- **Needs:** R-APP
- **Do:** in `app.json` set `"localisation": {"calendar": "ethiopic", "secondaryCalendar": "gregorian"}`; add a `DualCalendarDatePicker`; publish; open it on the device.
- **Expect:** dates show in the Ethiopian calendar (13 months) with the Gregorian date beside them; an unsupported value is refused (`PLX-1611`).
- **Why:** non-Gregorian calendars are first-class.
- **Look at:** pick 1 January 2030 Gregorian and compare with a trusted converter.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-015 — Other calendars

- **Needs:** L2-L10N-014
- **Do:** set `calendar` to `islamicUmalqura`, then `persian`; reopen the picker.
- **Expect:** each renders correct month names for the locale; dates outside the Umm al-Qura table range are reported, not guessed.
- **Why:** four calendars, own arithmetic, same result everywhere.
- **Look at:** [calendar wrong day runbook](../../runbooks/calendar-wrong-day.md).
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-016 — Locale fallback

- **Needs:** R-DEVICE-SHOP
- **Do:** delete one German text, publish; set the device to German Austria (`de-AT`).
- **Expect:** `de-AT` falls back to `de`, then to the default; the key itself never shows in a release build.
- **Why:** fallback chain (I18N-006).
- **Look at:** `l10n_missing` telemetry with the requested and resolved locale; [locale fallbacks runbook](../../runbooks/locale-fallbacks.md).
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-017 — Accessibility findings at publish

- **Needs:** R-SCREENS
- **Do:** add a button without a label, an image without alternative text, a 20 px tap target and low-contrast text; open **Publish** and read **Reports**, **Accessibility**.
- **Expect:** findings `PLX-1401`, `1402`, `1404`, `1403` with node paths; under `strict` or `maximum` they are errors that block the request, under `standard` warnings.
- **Why:** WCAG 2.2 AA is checked at publish (A11Y-001, A11Y-002).
- **Look at:** the publish stage marks the request *Blocked* ([publish blocked runbook](../../runbooks/publish-blocked-quality.md)).
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-018 — Accessibility report: create R-A11Y-REPORT

- **Needs:** R-RELEASE1, R-CLI
- **Do:** `plux release report --format html --out /tmp/a11y.html -C ~/plux-checks/shop --env development <sequence>`
- **Expect:** an HTML report with every check, each violation with its node path, and each waiver with author and justification.
- **Why:** evidence per release (A11Y-008).
- **Look at:** `--kind localisation` gives the localisation report.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-019 — Waive a check with a justification

- **Needs:** L2-L10N-017
- **Do:** add `"a11yWaivers": {"imageAlternative": "x"}` to the image, validate; then give a justification of at least ten characters.
- **Expect:** the short one fails (`PLX-1410`); the proper one passes and appears in the report. Under `maximum` saving needs `a11y.waive` (`PLX-1411`).
- **Why:** waivers are deliberate and audited (A11Y-005).
- **Look at:** the audit log entry for the waiver.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-020 — Screen reader on the device

- **Needs:** R-DEVICE-SHOP
- **Do:** turn on TalkBack or VoiceOver; swipe through `list`; use a button with the `announce` action.
- **Expect:** controls are read with role, label and state; focus order follows `focusOrder`; the announcement is spoken without moving focus.
- **Why:** runtime semantics for assistive technology (A11Y-001, A11Y-004).
- **Look at:** headings are announced as headings.
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-021 — Large text, bold text, reduce motion, high contrast

- **Needs:** R-DEVICE-SHOP
- **Do:** set the largest font size, bold text, reduce motion and high contrast in the device settings; reopen `shop`.
- **Expect:** text scales without clipping, animations are replaced by instant changes, the high-contrast token set is used.
- **Why:** platform settings are honoured (A11Y-006).
- **Look at:** the canvas **Text scale** preview showed the same result (L2-STU-016).
- **Result:** ☐ pass ☐ fail — notes:

### L2-L10N-022 — Studio itself: language and keyboard

- **Needs:** R-STUDIO
- **Do:** use Studio only with the keyboard for a minute (Tab, Enter, `Mod+K`); switch the profile language to Arabic.
- **Expect:** every control is reachable with a visible focus; the Arabic interface is mirrored.
- **Why:** the tool is accessible too (STU-011, STU-012).
- **Look at:** `make studio-e2e` runs the accessibility (axe) checks.
