# 0014. The Studio stack

- **Status:** **Accepted** (maintainer, 2026-10-24; P11 plan M-9, O-7)
- **Date:** 2026-10-24
- **Requirements:** `STU-001`, `STU-002`, `STU-004`, `SEC-101`, `CI-006`, `QA-007`

## Context and problem

Studio is a client-heavy editor behind sign-in. `STU-001` and `STU-002` fix React, Tailwind,
shadcn/ui, Monaco, Bun and a BFF, but several choices were open, and two of the spec's words
(Radix, Lighthouse CI) were replaced by later research without a record. `dependencies.md`
already points here for the P11 stack. The question: which stack, and how is it built, shipped,
cached and observed?

Sources: [p11-studio-decisions.md](../plans/p11-studio-decisions.md) (A3, A4.1–A4.22, A5.2,
A5.7–A5.10) and [p11.md](../plans/p11.md) (L-2, L-13, O-3, O-4, O-5, O-16).

## Decision drivers

- Security first: strict CSP, no session state in the BFF, one place that signs users in (`STU-002`, `SEC-101`).
- Editing latency and bundle size (`STU-004`, `STU-120`–`STU-123`).
- Components we own and style with our tokens, not a design language to fight (`STU-010`).
- Few runners and toolchains; an air-gapped install with nothing third-party.
- A reproducible build (`CI-006`) and measured performance (`QA-007`).

## Considered options

1. A React SPA built with Vite on Bun, a stateless Hono BFF, and the library set below.
2. Next.js or another server-rendering framework.
3. The Bun bundler and Elysia, or Radix-based shadcn.

## Decision

Chosen option: **1**.

### Application and server

- **React single-page app**; server rendering adds nothing behind sign-in. **Vite 8 (Rolldown)
  on the Bun runtime** builds it: Lingui, TanStack Router, Tailwind v4 and WebAssembly all have
  official Vite plugins, and code splitting is fine-grained (`STU-122`). `STU-001`'s "built with
  Bun" reads as Vite on the Bun runtime.
- **Hono BFF, stateless.** The server already issues `__Host-plux_session` and the CSRF token
  (ADR-0026). The BFF passes them through and keeps no session state. **Sign-in (L-13):** the server has no
  `/auth/*` routes; sign-in is `IdentityService` and `FederationService` RPCs that set the cookie,
  and every cookie call carries `X-CSRF-Token` and `X-Plux-Organization`. The BFF proxies those
  RPCs like any other and hosts the two pages the server lacks: the **OpenID Connect callback**
  (calls `CompleteOidcLogin`) and the **SAML assertion consumer** (a form `POST`, calls
  `CompleteSamlLogin`). It also sets per-request CSP nonces, proxies streams unbuffered, and
  starts W3C Trace Context on every call. `STU-002` is reworded accordingly.
- **API clients:** Connect-ES v2 and Connect Query, generated by a local `protoc-gen-es`
  (pinned in `studio/bun.lock`, no remote plugin, `CI-003`). Live data uses server streaming;
  there is no WebSocket and no service worker.

### Front end

- **Routing and data:** TanStack Router (typed, schema-validated search params), TanStack Query
  through Connect Query, TanStack Form with Zod 4 (`z.config({ jitless: true })` for the CSP),
  TanStack Table and Virtual.
- **State:** Zustand with Immer, stores per area created in a provider, never module-level. The
  edited document lives in Zustand; Query holds server-confirmed data.
- **Components:** **shadcn/ui on Base UI, not Radix.** shadcn is a generator, so the code is ours
  and styled with our tokens. Base UI is shadcn's default since July 2026, is actively released
  and has focus management and a direction provider. Radix is not deprecated but is not shadcn's
  direction, and cmdk would bring Radix back; the command palette is built on Base UI Dialog and
  Autocomplete instead. `STU-001` is reworded.
- **Styling:** Tailwind v4 with the theme generated from the `@plux/brand` tokens and Tailwind's
  defaults reset, so only token-backed utilities exist. One static stylesheet, no runtime
  CSS-in-JS.
- **Editors:** Monaco for full-screen JSON and Rust editors, CodeMirror 6 for inline PXL; both
  use one language service. **React Flow and dagre** for the action graph and auto-layout.
- **Icons:** Phosphor duotone, inlined through one `Icon` component with no runtime package.
- **Small pieces:** `@leeoniya/ufuzzy` for palette search; **`uqr` 0.1.3** for the pairing QR
  code (L-2), drawn from `encode()`'s matrix as SVG elements, its `renderSVG` string unused so
  the CSP needs no exception.
- **Quality:** Biome only; `bun test` with happy-dom and Testing Library; Playwright; axe. No
  ESLint, Prettier or Vitest.
- **Canvas toolchain:** see [ADR-0013](0013-plux-canvas.md). Localisation: [ADR-0094](0094-studio-localisation-and-direction.md).

### Dependency list

The list is decisions A3 as revised on 2026-10-22, plus `@leeoniya/ufuzzy`, `uqr`,
`protoc-gen-es`, the CanvasKit toolchain, and the design-gate detector (development only,
report-only in S0, gating from S3, O-4). Per O-3 each package enters
[dependencies.md](../engineering/dependencies.md) **in the step that first uses it**, with its
exact version and gzip size; nothing is allowed ahead of use.

### Deployment, caching, telemetry and versions

- **One image:** the static web files and the BFF, started beside the server roles (`DEP-002`);
  no CDN and nothing third-party.
- **Caching:** hashed assets (including the CanvasKit and validator WebAssembly) cached for a
  year, `immutable`, **Brotli-precompressed at build**; `index.html` is `no-cache` for a fresh
  nonce; API responses are never browser-cached.
- **Telemetry (minimal):** W3C Trace Context started by the BFF (`OBS-001`); uncaught errors and
  `web-vitals` timings through one BFF endpoint into the server's logs. No document content or
  personal data; sampled and rate-limited; an administrator switch; no browser SDK.
- **Versions (O-16):** Studio keeps its own semantic version (`workflow.md`) and declares the
  oldest server it supports; the image ships with each server release. An older Studio works
  against a newer server (additive API); open tabs show "Studio was updated, reload" after
  autosave flushes.
- **Reproducible build (`CI-006`):** the Studio build, including the WebAssembly, is built
  twice and compared.
- **Benchmarks (`QA-007`):** Playwright traces with `web-vitals`, failing on more than 10 %
  regression against their own baseline; this replaces the spec's Lighthouse CI.

## Consequences

- **Positive:** one validator-typed API path; no session store to attack; components we own;
  a small toolchain.
- **Negative:** Vite beside Bun means two tools; React Flow pins Zustand 4, so a second copy
  ships; Phosphor is stable rather than active, so we maintain the inlined paths.
- **Follow-up:** spec wording for `STU-001`, `STU-002`, `QA-007` and the §3 technology table
  (O-5, S0.0); a Revision of ADR-0026 for the BFF pass-through; `dependencies.md` rows per step.

## Conditions of release

Decision O-7: accepted with these reviews **open**. Work merges on the branch, but **no image is
published and 0.0.1 is not cut until each is closed**.

1. **Phosphor Icons:** the MIT notice for the inlined paths.
2. **axe-core and `@axe-core/playwright`:** MPL-2.0, development only, unmodified.
3. **Monaco and CodeMirror:** their notices.
4. **Every shipped package:** the notices collected into the image and checked by the licence gate.

## Options in detail

### Option 2 — Next.js

Server rendering and SEO add nothing to an editor behind sign-in. React Router's type safety
needs its framework mode. Rejected.

### Option 3 — Bun bundler, Elysia, Radix

`bun-plugin-tailwind` is young and no Lingui plugin exists for the Bun bundler. Elysia's types add
little to a Connect proxy and tie us to Bun. Radix is the wrong direction for shadcn. Rejected.

## Revision (2026-10-26, P11 S5.1: inline style attributes)

Monaco sets inline `style` attributes on its DOM, which `style-src 'self' 'nonce-…'` blocks. The
maintainer chose to add `style-src-attr 'unsafe-inline'`: it allows style attributes only;
`<style>` elements and stylesheets stay nonce-only and `script-src` is unchanged. A style
attribute cannot run script; the remaining risk is CSS-based UI tampering after an HTML
injection, which Trusted Types (`require-trusted-types-for 'script'`) already guards. Rejected:
rewriting Monaco's styles through CSSOM in the Trusted Types policy (fragile across Monaco
releases, slower), and replacing Monaco with CodeMirror for the full-screen editors (against
decision A4.6 and `STU-001`). The BFF test pins the directive.
